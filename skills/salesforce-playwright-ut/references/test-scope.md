# 実行対象の確定

2026/10/13のユーザー指定：このスキルは数式項目のロジックチェック、入力規則、ボタンの表示条件のテスト実行を扱う。「オブジェクトのテスト」「全件」「残りを継続」はこの範囲内の全件を意味する。

## 対象と前提操作

- catalogのcategoryが完全一致で「数式項目」：仕様書の入力値・条件から数式の実計算値を独立した期待値と照合する。文字列に「数式」があるだけの項目定義・ボタン表示条件は含めない。数式の出力URL等のロジックは扱うが、リンククリック・画面遷移だけを検証する独立ケースは含めない。
- categoryが完全一致で「入力規則」：指定入力で保存可否、拒否メッセージ、表示位置、保存値・未保存を確認する。
- categoryが「ボタン」で、テスト観点・操作・期待結果に表示／非表示の検証が明記されたケース：対象ボタンの表示条件をプロファイル別に実画面で確認する。[button-visibility.md](button-visibility.md) を読む。ボタン押下後の業務処理・画面遷移だけの独立ケースは対象外。
- 「画面イメージ」「ページレイアウト」に記載された表示条件ケースも、原文を確認してボタン表示条件を検証する行と確定したときだけ、catalogに `testKind: "button-visibility"` を付けて含める。元categoryと原文を保持し、文字列の部分一致だけで広げない。
- その他のカテゴリは対象外。独立した項目型・桁数・参照対象・権限・レイアウト割当・画面配置・注意文・親削除のテスト、専用データ準備、証跡作成を追加しない。
- 対象の数式・入力規則・ボタン表示条件の定義、必要な入力項目・参照検索条件・ユーザー・組織・保存状態は、その対象IDの前提／判定に必要な範囲で参照する。前提操作を別ケースのテスト成功として記録しない。資料不足の想定、未実装手順の追加、復旧で対象範囲を広げない。

## ブラウザー接続・データ準備の前

現行仕様書を再読込したcatalogに、下記のローカル抽出スクリプトを実行する。件数・ケースNoを固定しない。旧範囲の数式・入力規則だけの件数を現在の対象件数として流用せず、追加したボタン表示条件も現行資料から数える。

```powershell
& $pythonExe -B -X utf8 (Join-Path $skillDirectory 'scripts/select_test_scope.py') --catalog $catalogPath --source $sourceId --out $newScopePath
```

仕様書を限定しない実行では--sourceを省略する。単一ケースや再実施は--casesにカンマ区切りのIDを指定する。抽出されたcaseIdsだけを既存ランナーの--casesや実行計画へ渡す。上記の表示条件ケースと確定できないカテゴリ名が異なる／不明なケースは対象外として理由を記録し、表示ラベルの部分一致や旧番号で補わない。

```powershell
& $pythonExe -B -X utf8 (Join-Path $skillDirectory 'scripts/select_test_scope.py') --catalog $catalogPath --source $sourceId --cases $selectedIds --plan $casePlanPath
```

計画はcaseId付きの配列、またはcases配列を持つJSON。参照親等の依存準備は対象ケースの計画内に紐付け、独立した対象外ケースを計画へ追加しない。明示指定に対象外／不明なIDがあれば終了コード2で停止し、その指定ではブラウザー接続・作成・保存を開始しない。対象0件なら接続せず対象0件を報告する。--outは新規ファイル作成専用。JSON読取は.file-versionsの最新物理版に対応する。

## 出力前・中断再開

対象IDだけの結果を新しい実行に保存し、次の検証を通してからExcelを出力する。

```powershell
& $pythonExe -B -X utf8 (Join-Path $skillDirectory 'scripts/select_test_scope.py') --catalog $catalogPath --source $sourceId --cases $selectedIds --results $resultsPath
```

結果配列またはstate.results内のcaseId／target.caseIdを検証する。対象外・不明な結果IDは終了コード2。古い混在結果は削除・更新せず、今回の対象IDを抽出して新しい結果へ保存して再検証する。中断時は選択した対象内の実施済み結果と未完了だけを出力する。

実施一覧・ケースNoシート・総件数・OK/NG/保留・証跡は選択した対象ケースに限定する。対象外を「保留」に混ぜない。対象ID内の未実装・前提未成立・未確認は保留として残す。仕様書コピーは全行・書式を保持し、対象外行の実施日・結果・備考を変更しない。既存成果物をそのまま流用して対象外の結果を次回分に混ぜない。原本から新しいコピーを作る。

既存ランナーが対象指定を無視する、または出力器がcatalog全行へ判定を付ける場合は、接続前に対象限定の新しい実装を用意し、計画・結果ID検証を通す。対象外を完了させて出力を埋める方法は採らない。
