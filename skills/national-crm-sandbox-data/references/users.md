# ユーザー作成とパスワード

## User作成

明示依頼時のみ70人を追加。氏名は確認用1～70。件数は本店A9、本店B22、本店C5、地区・支店A11、地区・支店B11、集約化拠点A4、B4、C4。`assets/user-records.json`の所属コードとプロファイルの対応を維持する。対象環境の正式な対応表が異なれば停止して確認。

- 本店A：営業推進部の管理部室・グループ。本店B：創業支援部の部室・グループ。本店C：事業本部長付。
- 地区・支店A：東京中央支店／池袋支店の管理職。B：同支店の一般職員。
- 集約化拠点A：東京教育ローンセンターの管理職。B：同拠点の職員。C：同拠点のパート職員。

既存同名プロファイルを使う。Profile、UserRole、PermissionSet、PermissionSetAssignment、Group／GroupMemberを作成・編集しない。追加の権限セット・ロールが必要だと判断した場合はデータ操作を停止して相談する。ライセンス残数を読み取り、ユーザーを勝手に無効化して枠を空けない。

StaffIDはkn20001～kn20070を基準として対象環境と重複照合。既存別人との衝突を任意の採番で隠さず確認する。再実行の同一ユーザーはStaffID、氏名、プロファイル、所属、Usernameで一意に照合しスキップする。氏名だけでは判定しない。

Usernameは対象組織IDを含めて生成し、Salesforce全体の一意性に対応する。FederationIdentifierはStaffIDと合わせて照合し、実際のSSO利用に必要な設定は行わない。メールは同梱の配信されない値が基準。受信可能なアドレスや通知が必要なら明示指定を受ける。パスワード通知を勝手に送らない。

社員区分コード・旅費計算用科目日当コードは具体値が未確認で元データも未入力。補完を依頼された場合はコードを確認するまで停止する。CSVの保存値と、計算された所属コード、70人のプロファイル内訳を読戻し確認する。

## パスワード設定

その時点で明示された対象ユーザーとパスワードだけを設定する。User作成や業務データ移植の依頼から推定しない。対象IDを今回のユーザー一覧・ジャーナルで照合する。管理者や既存別人を対象へ混入させない。

RESTの `POST /sobjects/User/{対象ID}/password`、本文`NewPassword`を使用できる。`DELETE`のパスワードリセットやメール送信は実行しない。パスワードは安全な実行時入力でメモリ上だけへ渡す。引数・ソースコード・環境保存ファイル・CSV・ログ・ZIPへ含めない。API応答やエラーで値が露出しないよう扱う。

成功はHTTP 204応答で記録し、必要に応じて同じURLのGETで有効期限状態を確認する。パスワード値を読み戻せると説明しない。ログイン操作をしていない場合にログイン確認済みと報告しない。

パスワードポリシー拒否、本人確認、SSO、メール確認、MFA等の不明点・失敗では全書込みを停止する。指定値を勝手に別の値へ変更しない。パスワード設定が成功しても、認証設定の制限を解除して直接ログインを可能にしない。

公式仕様は実行時に必要な部分を確認する：
- [User Password REST API](https://developer.salesforce.com/docs/platform/api-rest/guide/resources-sobject-user-password.html)
- [メールアドレス変更](https://help.salesforce.com/s/articleView?id=000233025&language=en_US&type=1)

このスキルに過去のパスワードやアクセストークンは同梱しない。
