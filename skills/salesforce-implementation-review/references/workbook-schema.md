# Excelレビュー結果スキーマ

テンプレート `assets/review_template.xlsx` を複製し、詳細4シートと必須の `簡易指摘一覧` の計5シートを維持する。通常はレビューサマリの次に簡易シートを配置する。入力行を追加しても見出し、フィルター、固定行、入力規則、条件付き書式を保持する。

## 必須の簡易指摘一覧

指摘確認に使うシートとして、次の6列をこの順序で記載する。指摘IDの専用列は追加せず、対象欄に詳細と共通のIDを添える。

| 列 | 項目 | 記載内容 |
|---|---|---|
| A | 区分 | 不備・リスク・要確認。詳細の判定区分と一致させる |
| B | 優先度 | 詳細の重大度と同じ「重大・高・中・低・情報」を使用する |
| C | 対象 | 共通指摘ID、対象プロファイル／コンポーネント、短いファイル名と行・XML要素、または設計シート・セル |
| D | レビュー内容 | 何が問題か、期待値との差、影響・発生条件・未確認の前提を簡潔に記載する |
| E | 確認根拠 | 観察事実と設計書・セル、実装ファイル・行、公式資料等の根拠を短く記載する。確認できない場合は不足資料と確認限界を明示する |
| F | 対応案 | 必要な修正または確認の具体的な方法を記載する。レビュー内容や確認根拠と分ける |

- 詳細の指摘と1対1に対応させ、全件を同じ順番で記載する。似た指摘を束ねてIDや対象箇所を落とさない。件数・ID・区分・優先度を詳細シートと照合する。簡易シートの優先度を独自に変更しない。
- 長いパス、根拠の全文、確認方法の全文は詳細シートへ残し、簡易シートでは短いファイル名と安定した位置を使う。動的な行位置を推測で補わない。
- リスクや確認不能を確定不備に言い換えない。必要な発生条件や未確認の前提は短く残す。
- 指摘0件でも見出しと「指摘0件」を表示する。主要範囲が未確認なら、その制約も併記する。偽の指摘行や新しい指摘IDは作らない。
- 見出しを固定し、フィルターを付け、本文を折り返す。対象・内容・根拠・対応案が読める幅とし、本文を切らずに行高を合わせる。区分・優先度には入力規則と直接の識別色を設定する。
- 通常は同じブックに含める。別ファイルの指定がある場合は `<対象名>_簡易指摘一覧.xlsx` として作成し、詳細ブック名と共通IDを記載する。

## 1. レビューサマリ

レビュー対象、レビュー日、レビュー方式、総合判定、対象版、入力資料の充足状況、主要な制約を表示する。

重大度別件数と判定区分別件数は `指摘一覧` から集計する。確認済み・一部確認・未確認・対象外の件数は `確認条件・対象一覧` から集計する。指摘件数が0でも、未確認範囲があれば `可` と表示しない。

## 2. 指摘一覧

1指摘・1修正箇所を1行にする。

| 列 | 項目 |
|---|---|
| A | 指摘ID |
| B | 関連指摘ID |
| C | 重大度 |
| D | 判定区分 |
| E | 確度 |
| F | レビュー観点 |
| G | 対象種別 |
| H | コンポーネント名 |
| I | 実装ファイル |
| J | 実装行・XML位置 |
| K | 設計書 |
| L | 設計シート・節 |
| M | 設計行・セル・ページ |
| N | 指摘内容 |
| O | 根拠となる事実 |
| P | 影響・発生条件 |
| Q | 推奨対応 |
| R | 修正時の注意点 |
| S | 確認・テスト方法 |
| T | 根拠資料 |
| U | 対応状況 |
| V | 担当者 |
| W | 回答・対応内容 |

重大度、判定区分、確度、対応状況にはテンプレートの入力規則を使用する。レビュー時点でU～Wは原則空欄とする。再レビューではUを更新し、過去の回答を消さない。

## 3. 設計実装対応表

| 列 | 項目 |
|---|---|
| A | 対応ID |
| B | 設計書 |
| C | 設計シート・節 |
| D | 設計行・セル・ページ |
| E | 設計項目・要件 |
| F | 要件重要度 |
| G | 実装状態 |
| H | 対象種別 |
| I | コンポーネント名 |
| J | 実装ファイル |
| K | 実装行・XML位置 |
| L | 確認結果・根拠 |
| M | 関連指摘ID |
| N | 備考・不足情報 |

設計要件を省略せず、全件を載せる。一つの要件が複数実装に対応する場合は行を分け、同じ対応IDを使用する。

## 4. 確認条件・対象一覧

| 列 | 項目 |
|---|---|
| A | 管理ID |
| B | 区分 |
| C | 種別 |
| D | 名称 |
| E | パス・URL |
| F | 版・APIバージョン |
| G | 更新日・確認日 |
| H | 確認状態 |
| I | 対象範囲 |
| J | 対象外・未確認範囲 |
| K | 備考・制約 |

区分は `設計書`、`実装`、`テスト`、`公式資料`、`案件ルール`、`前回レビュー` 等を使う。公式URLには確認日を必ず付ける。

## 表現と書式

- 日本語を標準とし、API名、クラス名、メタデータ名は原文を維持する。
- テーブル見出しは固定し、フィルターを有効にする。
- 長文列は折り返し、識別子・位置列は過剰に折り返さない。
- `重大` と `高`、`不備`、未確認状態を色で識別する。色だけに意味を依存させない。
- Excelアプリで識別色が消える事象を防ぐため、提出時点の区分・重大度・確認状態に応じた背景色と文字色をセルへ直接設定する。条件付き書式は値を変更した際の補助として併用する。表の帯色より識別セルの直接書式を優先させ、ヘッダーの色も直接設定する。
- 区分は不備＝薄赤、リスク＝薄黄、要確認＝薄青を基本とする。重大＝赤系、高＝橙系、未確認／一部確認／確認不能＝薄黄。RGBの明示色を使い、テーマ色だけに依存しない。文字の区分も必ず表示する。
- 保存後のXLSXを再読込して代表セルの塗りつぶし・文字色、フィルター、固定行、条件付き書式を確認する。表示差がある場合はOOXMLのセルstyle参照・fill/fontと条件付き書式を分けて調べ、プレビュー上の色だけを根拠に合格としない。
- Excelアプリを操作できる環境では保存済みファイルを開いて代表区分を確認する。操作できない／ファイルが使用中なら直接書式の保存まで検証し、Excelアプリ表示は未確認と報告する。色消失の原因を未確認のまま断定しない。
- 区分や状態を変更した際は識別色も再生成・再確認する。直接書式はレビュー時点の値に対応するため、値の更新後に古い色を残さない。
- 行番号は空行とコメントを含む1始まりとし、異なる数え方なら明記する。
- 結合セルを参照する場合は左上セルを記載する。
- 根拠資料は設計書名、案件決定ID、公式URL等を具体的に記載する。

## 定型生成スクリプト

`scripts/create_review_workbook.mjs` は、表計算スキルが提供する `@oai/artifact-tool` 実行環境で使用する。入力JSONは次の形とし、各配列の列順は本書の表に合わせる。

```json
{
  "summary": {
    "target": "対象名",
    "reviewDate": "YYYY-MM-DD",
    "method": "静的レビュー",
    "overall": "条件付き",
    "version": "設計版・APIバージョン",
    "inputs": "入力資料の要約",
    "limitations": "未確認範囲",
    "reviewer": "担当"
  },
  "findings": [],
  "simpleFindings": [],
  "traceability": [],
  "inventory": []
}
```

`simpleFindings` は省略可能。指定時の各行は `[指摘ID, 区分, 優先度, 対象, レビュー内容, 確認根拠, 対応案]` とする。先頭のIDは照合用の入力情報で、Excelには専用列を作らず対象欄に `[指摘ID]` として表示する。対象文字列自体へのIDの重複記載は不要。`findings` と件数・順序・ID・区分・優先度を一致させる。

未指定時は詳細の判定区分・重大度・対象名・位置・指摘内容・観察事実・設計位置・実装位置・推奨対応から6列を生成する。根拠となる発生条件や未確認の前提が短縮で失われていないか、納品前に確認する。旧4項目入力 `[指摘ID, 区分, 指摘箇所, 指摘内容・確認事項]` も読み込み可能だが、対象以外の本文・根拠・対応案は詳細から分離して生成する。旧形式の混在した本文をそのまま1列に転載しない。新規作成では7項目入力または省略を使用する。判定は `findings` を正とする。

テンプレートを上書きせず、別の出力パスを指定する。

```text
node scripts/create_review_workbook.mjs --mode review --data review.json --output <成果物.xlsx>
```

スクリプトは簡易シートとセルへの直接色設定を含めて出力する。出力後は必ず表計算スキルの手順で数式、値、入力規則、表、全5シートの表示、保存後の識別色を検証する。
